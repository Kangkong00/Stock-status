# 재고관리

엑셀 매크로로 현재고를 직접 맞추던 방식을 대체하는 **원장 기반 재고관리 프로그램**입니다.
인터넷 없이 내 PC 안에서만 동작하고, 데이터는 파일 하나(`data/stock.db`)에만 저장됩니다.

---

## 왜 이런 구조인가

기존 방식이 자꾸 밀리는 이유는 **현재고 숫자를 사람이 직접 맞추기 때문**입니다.
한 번 빠뜨리면 그 오차가 영원히 남고, 나중에 어디서 틀렸는지 찾을 수도 없습니다.

이 프로그램은 그 관계를 뒤집습니다.

| | 기존 (엑셀 매크로) | 이 프로그램 |
|---|---|---|
| 사람이 입력하는 것 | 현재고 숫자 | 입고/출고 **사건**만 |
| 현재고 | 사람이 계산해서 기입 | 시스템이 항상 합산해서 도출 |
| 틀렸을 때 | 어디서 틀렸는지 못 찾음 | 전표 단위로 추적·취소 가능 |
| 상품명이 제각각일 때 | 매번 사람이 판단 | 한 번 알려주면 계속 기억 |
| 발주 시점 | 눈으로 훑어봐야 앎 | 시스템이 먼저 알려줌 |

핵심은 **현재고를 저장하지 않는 것**입니다. 원장(입출고 기록)이 유일한 진실이고,
현재고는 언제나 그 합계입니다. 그래서 재고가 "안 맞는" 상황이 구조적으로 생기지 않습니다.

---

## 상품명 3층 구조

주문서에 오는 상품명은 매번 조금씩 다릅니다.
이걸 그대로 품목으로 쓰면 같은 볼펜이 3개 품목으로 쪼개져 재고가 영원히 안 맞습니다.
반대로 코드만 쓰면 나중에 명세서와 대조할 수 없습니다. 그래서 역할을 나눕니다.

| 층 | 역할 | 예시 |
|---|---|---|
| **표준품목** | 재고를 세는 **유일한** 단위 | `PL-0012 / 모나미 볼펜 / 검정 0.5mm / EA` |
| **별칭** | "주문서엔 이렇게 적혀 온다" 목록 (1품목 : N별칭) | `흑색볼펜0.5mm 모나미`, `볼펜(흑) 0.5` |
| **원문** | 입출고 기록마다 주문서 문구를 그대로 보존 | 추적·대조용, 수정 불가 |

### 처리 흐름

```
상품명 입력 / 명세서 업로드
   ↓ 정규화 (전각→반각, 공백·특수문자 정리, 단위·색상 표기 통일, 수식어 제거)
   ① 품목코드·바코드·별칭 완전일치 → 자동 기록          ← 사람 손 0
   ② 유사도 후보 제시 → 클릭 1번
        → 그 순간 별칭으로 자동 학습 → 다음부터 ①로 처리
   ③ 후보 없음 → '확인 대기'에 적재 → 하루 끝에 몰아서 처리
```

**쓸수록 일이 줄어듭니다.** 처음 2~3주는 ②를 좀 하시지만, 그 뒤엔 대부분 ①로 통과합니다.

### 규격 오매칭 방지

이름이 비슷해도 **규격 숫자가 어긋나면 절대 자동 매칭하지 않습니다.**
재고 시스템에서 가장 위험한 사고를 구조적으로 막는 장치입니다.

| 비교 | 유사도 | 판정 |
|---|---|---|
| `모나미 볼펜 검정 0.5mm` ↔ `흑색볼펜0.5㎜ 모나미` | 0.60 | 후보 제시 (확인 1클릭) |
| `모나미 볼펜 검정 0.5mm` ↔ `모나미 볼펜 검정 **0.7mm**` | 0.25 | **차단** |
| `A4 복사용지 80g 500매` ↔ `복사지A4 80g 500매` | 0.74 | 후보 제시 |
| `A4 복사용지 80g 500매` ↔ `A4 복사용지 **75g** 500매` | 0.33 | **차단** |
| `건전지 AA 4개입` ↔ `**AAA**건전지 4개` | 0.76 | 자동 채택 안 함 (확인 필요) |

## 시작하기

### 1단계 — 파이썬 설치 (최초 한 번만)

<https://www.python.org/downloads/> 에서 내려받아 설치합니다.
설치 화면 맨 아래 **`Add Python to PATH`** 를 반드시 체크하세요. (이거 안 하면 실행이 안 됩니다)

이미 설치돼 있으면 건너뛰세요.

### 2단계 — 프로그램 내려받기

<https://github.com/Kangkong00/Stock-status/tree/claude/inventory-automation-plan-x6zstr>
접속 → 초록색 **`Code`** 버튼 → **`Download ZIP`**

내려받은 ZIP 을 **압축 풀기**. 바탕화면이나 `C:\재고관리` 처럼 찾기 쉬운 곳에 두세요.
(경로에 한글이 있어도 됩니다)

### 3단계 — 실행

압축 푼 폴더 안의 **`실행.bat`** 더블클릭. (맥/리눅스는 `실행.command`)

- 최초 1회는 필요한 것을 자동 설치하느라 **1~3분** 걸립니다. 검은 창을 닫지 마세요.
- 설치가 끝나면 **브라우저가 저절로 열리고 재고 현황이 나옵니다.**
- 안 열리면 주소창에 `http://127.0.0.1:8765` 를 직접 입력하세요.
- 끝낼 때는 검은 창에서 `Ctrl+C`. 검은 창을 닫으면 프로그램도 꺼집니다.

> 윈도우가 "PC를 보호했습니다" 라고 막으면 **자세히 → 실행**을 누르세요.
> 백신이 막는 경우도 **허용**을 눌러주시면 됩니다.

#### 실행.bat 이 안 될 때 — 직접 실행하기

`실행.bat` 이 오류를 내면 명령어 두 줄로 직접 띄울 수 있습니다.

1. 압축 푼 폴더를 **파일 탐색기**로 엽니다.
2. 주소창(폴더 경로가 보이는 칸)을 클릭하고 `cmd` 를 입력한 뒤 **Enter**.
   그 폴더 위치에서 검은 창이 열립니다.
3. 아래를 한 줄씩 붙여넣고 Enter:

```
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

`py` 에서 오류가 나면 `py` 대신 `python` 을 쓰세요.
두 번째 실행부터는 마지막 줄만 입력하면 됩니다.

오류 메시지가 나오면 그 내용을 그대로 알려주세요.

기존 엑셀에서 이관한 자료가 **이미 들어 있습니다.** 따로 넣으실 것이 없습니다.

파이썬 설치 없이 쓰고 싶다면, 윈도우 PC 에서 한 번만:

```

```

`dist/재고관리.exe` 하나가 만들어집니다. 이 파일만 옮겨도 그대로 동작합니다.

## 나중에 새 엑셀을 넣을 때 — `엑셀 업로드`

파일을 끌어다 놓으면 **열 이름을 자동으로 알아봅니다.** 양식을 맞출 필요가 없습니다.

- 제목 행이 위에 있어도 진짜 헤더 행을 찾아냅니다
- `품목코드`/`품번`/`관리번호`, `현재고`/`재고수량`/`잔량` 처럼 표현이 달라도 인식합니다
- 틀린 부분만 화면에서 고치면 됩니다
- **시험 실행**으로 반영 전 결과를 미리 볼 수 있습니다 (DB 를 건드리지 않음)
- 실제 반영 직전에 **자동 백업**이 만들어집니다

`품목 마스터` → `입출고 내역` 순서로 두 번 올리시면 과거 이력까지 이관됩니다.

### 2. 재고기준 정하기

품목마다 **재고기준(안전재고)** 을 정하세요. 이 수량 이하로 떨어지면
대시보드 맨 위와 메일로 알려드립니다. 기준을 정하는 요령:

> **재고기준 ≈ 일평균 출고량 × (발주 후 도착까지 걸리는 일수) + 여유분**

품목 상세 화면에서 일평균 출고량과 소진 예상일을 확인할 수 있습니다.

### 3. 메일 리포트 켜기 — `설정`

받는 사람과 발송 시각을 정하면, 매일 아침 **발주해야 할 목록**이 재고현황 엑셀과 함께 도착합니다.
주간 리포트에는 장기 미사용 재고와 분류별 요약이 추가됩니다.
보고할 변화가 없는 날은 보내지 않습니다.

> 네이버·구글 메일은 **계정 비밀번호가 아니라 '앱 비밀번호'** 를 발급받아 넣어야 합니다.
> 네이버: 내정보 → 보안설정 → 애플리케이션 비밀번호
> 구글: 계정 → 보안 → 2단계 인증 → 앱 비밀번호

## 매달 하는 일 — 재고실사

아무리 잘 기록해도 파손·분실·오출고로 전산과 실물은 조금씩 어긋납니다.
**정기 실사가 재고를 완벽하게 유지하는 유일한 현실적 방법입니다.**

1. `재고실사` → `실사 시작` (품목이 많으면 분류별로 나눠서)
2. 엑셀 시트를 뽑아 창고에서 세거나, 화면에서 바로 입력
3. 실물 수량만 넣으면 차이와 금액 영향이 자동 계산됩니다
4. `실사 확정` → 차이만큼 조정 전표가 자동 생성되고 재고가 실물에 맞춰집니다

조정 내역은 `ADJ` 전표로 남으므로 나중에 감모가 얼마였는지 추적할 수 있습니다.

## 데이터와 백업

모든 데이터는 **`data/stock.db` 파일 하나**에 들어 있습니다. 이 파일만 복사하면 전체가 옮겨집니다.

- `data/backups/` 에 자동 백업이 쌓입니다 (임포트·실사 확정 직전마다)
- 되돌리려면 백업 파일을 `data/stock.db` 로 덮어쓰고 프로그램을 다시 시작하세요
- `설정` 화면에서 수동 백업과 보관 개수 설정이 가능합니다

USB나 클라우드 동기화 폴더에 `data` 폴더를 주기적으로 복사해 두시길 권합니다.

## 설계상 지키는 규칙

1. **현재고는 저장하지 않는다.** 항상 원장 합산으로 도출한다.
2. **기록은 지우지 않는다.** 취소는 `voided` 플래그로만 하고 이력은 남긴다.
3. **원문 상품명은 수정하지 않는다.** 나중에 명세서와 대조해야 한다.
4. **규격이 어긋나면 자동 매칭하지 않는다.** 사람 확인을 받는다.
5. **되돌릴 수 없는 작업 전에는 백업한다.** (임포트, 실사 확정)
6. **밖으로 나가지 않는다.** 127.0.0.1 전용, 외부 CDN·폰트 미참조.
